Live Price Lookup

Compare Supplier Prices in Real-Time

  1. Click the Live Price Lookup tab (Search icon)
  2. Enter one of: an internal SKU, a manufacturer part number, a DigiKey stock code (…-ND), or an LCSC stock code (C + digits)
  3. The system detects what you typed and queries the right suppliers:
    • DigiKey (OAuth2 client_credentials or refresh token)
    • Mouser Electronics
    • LCSC (live lookup + cached import)
    • Nexar / Octopart — aggregator covering Arrow, Heilind, Avnet and dozens more
    • Element14 / Farnell / Newark (Avnet)
    • TME (Transfer Multisort Elektronik)
  4. Look for the notice above the result cards — it tells you when the search term was translated (SKU→MFN or DigiKey stock code → real MPN) or when a supplier was skipped because it wouldn't recognise the code (LCSC codes).
  5. View API usage meters to track credit consumption per provider
  6. Click "View listing" to visit the supplier webpage
💡 Tip: The system caches pricing data for 30 days per (provider, part, quantity) to keep API costs down. Non-USD quotes (GBP, EUR, PLN, CAD, AUD, SGD) are converted using daily exchange rates cached alongside them.
✅ Fuzzy-match trap avoided: Sending an LCSC stock code like C105882 to Mouser or Element14 used to return unrelated $200+ parts. Live Price Lookup now recognises those codes and only asks LCSC. If you need cross-supplier quotes for the same part, search by the real manufacturer part number instead.

Bulk pricing

An item's bulk price is what a supplier charges per unit at the bulk quantity (1 000 by default). Bulk pricing asks DigiKey, Mouser, LCSC, Nexar, element14 and TME for each item, converts the answers to rand and dollars at the stored exchange rate, and keeps the cheapest.

A run writes only the bulk price (R and $). It never changes stock, part numbers, links or the item's cost. (The old "Apply live rates" button sent whole items back from the copy the page had loaded, which could undo stock movements made in the meantime and overwrite the cost. It is gone.)

Run bulk pricing

  1. Open the Bulk Pricing tab under Pricing Directory.
  2. Under Price, choose the items: Items due for re-pricing, Items with no bulk price, Every item with a part number, or Ticked items (tick rows in the list below; ticking switches to this choice).
  3. Click Preview to see what would change without saving anything, or Update prices to save. Updating always asks first; a preview asks when it covers more than 50 items, because every lookup counts towards the daily supplier API limits.
  4. The run happens on the server, one item at a time. The progress card shows how far it has got; you can leave the page and come back. Stop finishes the item in hand and stops.
  5. When it finishes, the card shows how many items were updated, unchanged, held back, without a price, skipped or failed, and Why items were not updated, grouped by reason. Show items lists every item with its old and new price.

Only one run happens at a time. If one is in progress (yours, someone else's or the automatic one), the buttons wait until it finishes.

What each result means

ResultMeaning
UpdatedThe new bulk price was saved.
UnchangedThe suppliers' price matches the one on file. Nothing was written.
Held backThe cheapest price was above the hold-back limit ($50 a unit by default), which almost always means the supplier matched the wrong part. It was not saved; check the part number.
No priceNo supplier had a price for the part number. Tried again after 7 days.
SkippedThe item has no part number, or the daily supplier API limit ran out. A skipped item stays due, so the next run picks it up.
FailedThe supplier lookup or the save still failed after three tries. Tried again after 7 days.

The part number looked up is the item's first real manufacturer part number (ManPN 1–5), or failing that its first supplier part number (SupPN 1–5). DigiKey stock codes (…-ND) are resolved to the manufacturer part number first, and LCSC codes (C + digits) are only sent to LCSC, as in Live Price Lookup.

Automatic re-pricing

  • Every day at 04:30 (02:30 UTC) the server re-prices the items whose last successful bulk price is more than 35 days old, and items never bulk priced, oldest first, up to 100 per run.
  • An item that got no price, or failed, waits 7 days before it is tried again, rather than using up API calls every day.
  • If a run is already in progress at 04:30, the automatic run is skipped for that day. If the server was down at 04:30, it catches up 10 minutes after it starts, unless an automatic run happened in the last 20 hours.
  • Automatic runs appear under Recent runs as Automatic, with the same summary as a manual run. The same daily job removes expired price history.

The "Last bulk priced" list

Every item, with its bulk price, when it was last bulk priced and how (automatic or manual), its last result and the reason, the last change (old → new) and when it is next due for automatic re-pricing.

  • Show: All, Due, Problems (held back, no price or failed last time), Never priced, No bulk price, No part number. Each shows how many items it covers.
  • Sort: oldest update first, problems first, most recently updated, or stock code.
  • Search by stock code, name or part number.
  • History on a row shows that item's bulk pricing over the history period: when, which run, the result, the old and new price, and the supplier.

Price history and how long it is kept

Each run records, for every item it checks, the old and new price, the supplier, the result and any error, with the time and whether the run was manual or automatic. Previews are recorded against their run, so you can see what they found, but are not part of an item's history.

History is kept for 40 days by default (never less than 30), then removed. Each item's latest result, as shown in the list, is kept however old it is.

💡 Why 40 days, not 30: items are re-priced 35 days after their last price. With 30 days of history, the record of an item's previous change would be gone before it was re-priced, so you could never compare two runs. 40 days covers a full cycle. If someone sets history shorter than the re-price interval, the page shows a warning.

How live lookup matches parts

Smart part matching

The Pricing Directory now recognises what kind of code you typed and routes the query intelligently instead of blindly asking every supplier.

  • Internal SKU → MFN: if you type one of your own stock codes, the system looks up its stored manufacturer part number and searches suppliers by that instead.
  • DigiKey stock codes (anything ending in -ND): DigiKey is asked first to resolve the code to the real manufacturer part number, and every other supplier is then queried for that real MPN. Comparable quotes, no double DigiKey call.
  • LCSC stock codes (C followed by digits, e.g. C105882): only LCSC is queried. Other distributors would fuzzy-match to unrelated parts (a 100 nF capacitor was once priced at $241 via Pasternack this way).
  • Full supplier fan-out now covers DigiKey, Mouser, LCSC, Nexar (Octopart aggregator: Arrow, Heilind, Avnet, …), Element14/Farnell/Newark and TME.
  • Multi-currency: non-USD quotes (GBP, EUR, PLN, CAD, AUD, SGD) are converted to ZAR/USD automatically. Exchange rates refresh daily via a single call and are cached for 30 days.

Distributor stock code detection

Roughly 25% of items in the catalogue carry a distributor stock code in the manufacturer part number field. Live Price Lookup now handles those gracefully as described above; over time, cleaning those fields to the real MPN will give you the best cross-supplier price coverage.
