Purchase orders

Purchase Orders — Supplier & Customer modes

Create Purchase Orders with Mode Selection

  1. Click Purchase Orders tab
  2. Click Create PO
  3. Select Order Type (NEW!):
    • Supplier Mode: For ordering regular inventory/components
      • Shows inventory items (non-production stock)
      • Select from suppliers list (Mouser, Digikey, LCSC, etc.)
      • Use for component sourcing and inventory replenishment
    • Customer Mode: For customer production orders
      • Shows production stock items only
      • Select from customers list (Bokpoort, Damlaagte, DEWA, Sasol, etc.)
      • Use for custom manufacturing and special orders
  4. Dropdown automatically updates: Shows suppliers or customers based on selected mode
  5. Set order date and expected delivery date
  6. Add line items using smart autocomplete:
    • Items filtered based on selected mode (inventory vs production)
    • Auto-populate unit price and description
    • Select tax rate
  7. System calculates subtotal, tax, and total automatically
  8. Click Save Draft to save without sending
  9. Click Save & Send to submit to supplier/customer

Free-typed SKUs on PO & bill lines

The SKU / Part# input on purchase-side line editors now accepts free-typed values, not only rows that exist in inventory. A supplier's own SKU that isn't yet in your catalogue no longer forces you to bail out and add the item first.

Deleting a purchase order

  • Drafts: anyone can delete a draft, with the Delete button in the order's viewer.
  • Sent, received or cancelled orders: only an admin can delete these. Admins get a bin icon on every row of the list, and the Delete button in the viewer whatever the status.
  • What is removed: the order and its lines. Stock and the ledger are not affected, because a purchase order never moves either; bills do.
  • Bills raised from the order stay in the books. They only lose the link back to the order, and the confirmation lists them by number before you agree.
  • Every deletion is written to the activity log: who deleted it, the order number, and any bills that were unlinked.
⚠ This cannot be undone. If the order might still matter, use Cancel instead: it keeps the record and marks it as not going ahead.

Bills & landed cost

Managing Bills (Purchase Invoices)

  1. Click Bills tab
  2. Click Create Bill
  3. Select supplier
  4. Enter bill number and date
  5. Add line items with amounts and accounts
  6. Save and track for payment processing

Deleting a bill

A bill is in the books, so deleting one undoes it rather than just removing a row. Before you confirm, the app lists exactly what will go with it.

  • Drafts: anyone can delete a draft, with the Delete button in the bill's viewer. A draft has not posted anything, so nothing else changes.
  • Posted, paid or void bills: only an admin can delete these. Admins get a bin icon on every row of the list, and the Delete button in the viewer whatever the status.
  • The ledger: a reversing entry is posted, dated the day you delete, which cancels the bill out. The original entry and its reversal both stay in the journal, exactly as when you void a bill. A bill that is already void was reversed when it was voided, and is not reversed again.
  • VAT201: the bill comes off the return for the period of its bill date. If that period has already been submitted to SARS, the report will no longer match what you filed.
  • Payments: a payment recorded against that bill alone is reversed and removed with it, the same as Void Payment. The confirmation names each one, and the button reads Delete bill and payment.
  • Stock: stock the bill booked in stays in inventory, as it does when a bill is voided. The confirmation lists it; adjust it under Items & Inventory if those goods never arrived.
  • The scanned receipt is deleted with the bill. Save a copy first if you need one.
  • The purchase order the bill came from is not changed, and can be converted to a bill again.
  • Every deletion is written to the activity log: who deleted it, the bill number, and the payments that were voided.

When a bill cannot be deleted yet

The app says why instead of asking you to confirm, and nothing is changed:

  • Its payment also pays other bills. Void that payment under Payments Made first, then delete the bill.
  • Its payment is matched on a bank statement. Unmatch it under Accounting > Bank Reconciliation first.
  • A landed cost batch uses it. Delete the batch first if it is still a draft. A posted batch has already repriced stock from the bill, so that bill has to stay.
⚠ This cannot be undone. If the bill is real and only needs to stop counting, use Void instead (for a paid bill, void its payment first): it reverses the ledger entry but keeps the bill and its receipt on record.

Landed Cost

New tab under Bookkeeping → Purchases → Landed Cost. Bolt freight / duty / bank-charge bills onto the underlying goods bill so each unit's cost reflects its true landed price — not just what Digi-Key charged.

  1. Record the goods bill as normal (e.g. BILL-2026-0042 at $52.20 for 5000 resistors).
  2. Record the freight and duty bills separately (BILL-2026-0043 R850, BILL-2026-0044 R1240).
  3. Create a Landed Cost Batch — pick the goods bill on the left, the addon bills on the right (each tagged Freight / Duty / Bank / Other), and an allocation method (BY_VALUE = proportional to line total, BY_QTY = per unit).
  4. Preview shows every affected line's original → new unit cost + rounding delta.
  5. Post writes a snapshot per line, rewrites inventory.current_cost_dollar, and posts DR Inventory / CR Default Expense for the total addon.

Every downstream COGS + margin report picks up the landed cost automatically — no follow-up steps.
